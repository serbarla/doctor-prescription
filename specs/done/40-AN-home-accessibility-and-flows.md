- Source: `context/screens/Home.md` §§2.1–2.3, 3.3, 3.6–3.7, 4.1–4.3 and 6; `context/screens/done/Verify.md` §2.4 for the shared re-entry form.
- Depends on: `39-AM` must pass before this phase starts; completed `17-Q` and `18-R` supply the primitives.
- Project root: the `doctor-prescriptions` repository root. All paths and commands below are relative to it.
- Owned files: `persona-sanus/src/main.rs`, `persona-sanus/src/ui/marketing.rs`, `persona-sanus/src/ui/domain.rs`, `persona-sanus/src/ui/gallery.rs`, `persona-sanus/assets/main.css`.
- Gate: `cargo check --manifest-path persona-sanus/Cargo.toml`.
- User-interface verification: required — run Home with signed-out and synthetic staff sessions, and exercise the actual verification form, public result re-entry, and both gallery examples; record §3 evidence.
- Result carried forward: Home exposes the meaningful tags and labeled code field without announcing fictional mock content; empty submits have an accessible description, and existing role and public verification paths still work.

## 1. Problem and decision

- Problem: assistive technology gets fictional A4 content, and the form's visible empty-code error is not the input's accessible description.
- Decision: fix those semantics at the two shared primitives that own them, give each code form instance a stable error ID, and leave Home's role resolution and the result route unchanged.
- Open questions: None.

## 2. Objectives and scope

- [x] 1. - [x] 2. Associate the existing inline verification error with its labeled input — requirements: in `ui/domain.rs` make the signature of `VerificationCodeForm` `pub fn VerificationCodeForm(#[props(default)] button_variant: ButtonVariant, error_id: &'static str, on_submit: EventHandler<String>) -> Element`; run LSP references before changing it and migrate all four call sites together: `Home` → `"home-verification-code-error"`, `Verify` → `"verify-reentry-code-error"`, and the Primary/Secondary frames in `ui/gallery.rs` → `"gallery-primary-verification-code-error"` / `"gallery-secondary-verification-code-error"`. Replace only this form's `TextField` with `label.ui-field` wrapping `span.ui-field-label` and `input.ui-input` using the existing field classes, label `Código de verificación`, placeholder `PS-7K2F-9Q`, text input, `autocomplete="off"`, `spellcheck=false` and the existing value/oninput signal updates. Use a boolean error signal initially false; set `aria_invalid` from it and `aria_describedby: invalid.then_some(error_id)` using its current value. `TextField` has no external error-description prop; use the local label/input markup to keep the generic component unchanged, and remove the now-unused `TextField` import from `domain.rs`. Render one `div.ui-code-form-error` with `id: error_id` containing `ErrorText { text: "Ingresa el código de verificación.".to_owned() }` only when invalid, immediately after the submit button in DOM, visually below the field row. In CSS replace `.ui-code-form .ui-error` with `.ui-code-form-error` for the existing `grid-column: 1 / -1` rule; preserve the two-column desktop / stacked mobile form, button variants, and all other form consumers.
- [x] 3. Preserve verification and CTA routing — requirements: keep `event.prevent_default()`, `value().trim().to_uppercase()`, and the same submit callback; on empty/whitespace set invalid and return without navigation/request, on non-empty clear invalid before invoking the callback. Keep Home `navigator.push(Route::Verify { code })` and Verify `requested.set`/`navigator.replace` unchanged, with no new client validation or redirect. Keep Home's session/profile match unchanged: no session `Emitir receta` → `/login`; doctor/nursing `Emitir receta` → `/prescriptions/new`; administrator/secretary `Ver recetas` → `/prescriptions`; no profile/role `Completar perfil` → `/settings/profile`. Cierre mirrors the target and stays outlined. Keep the plain `#verificar` Hero/Footer anchors and the one explicit doctor/date/number disclosure in the mint band.

### Out of scope / no-go

- No auth, permissions, sync/offline, database, API, normalization policy, result-card, Navbar/Footer behavior or general field primitive changes; no fake fixtures in product code, genuine PHI, style redesign, or unit tests. Preserve the existing `ErrorText` role and all `es-EC` copy.
